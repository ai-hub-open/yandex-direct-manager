# Campaign Structure — разбиение семантики на кампании и группы

Используется на Шаге 5 пайплайна (после `wordstat-filter`, перед `negative-keywords-builder`). Задача — превратить отсортированную семантику в **чёткую структуру кампаний и групп**, готовую для заливки через MCP.

Без правильной структуры кампания «варит всё в одном котле»: одна реклама на разные углы запроса, перебитая статистика, невозможная оптимизация, кросс-минусация не работает.

## Главный принцип

**Одна кампания = один однородный угол атаки.** Если ключи отвечают на разные намерения пользователя — это разные кампании. Если объявления должны звучать одинаково для всей группы запросов — это одна группа.

## Две модели структуры (ЕПК vs классика)

На Шаге 5 маркетолог выбирает модель (гейт в `SKILL.md`). Результат — в `_state.json` поле `ad_model`.

### Модель `epk_combined` (рекомендованная)

- **1 угол / сегмент / лендинг → 1 РК.** Внутри — **1 группа, 1 комбинаторное объявление** (несколько заголовков/текстов/картинок/видео — лимиты в `yandex-direct-specs.md`).
- **Поиск и РСЯ НЕ разделяются на отдельные кампании** — одна РК обслуживает оба размещения (плюс Галерею и Карты).
- Ключи Шага 4 идут в эту же РК: НЧ/СЧ/ВЧ как ключевые фразы + автотаргетинг для сети. **CSV Шага 4 не меняются** — меняется только сборка структуры здесь.
- Разделы «Жёсткие правила агентства» 1 (Поиск vs РСЯ раздельно) и 6 (РСЯ отдельной кампанией) в этой модели **не применяются**. Углы/сегменты (Премиум, Срочно, Бренд, B2B) по-прежнему разносятся по отдельным РК — правила 2, 4, 5 действуют.
- В `05_campaign_structure.json` каждая кампания получает `"combined": true`, а корень — `"ad_model": "epk_combined"`.

### Модель `classic`

- Всё, что описано ниже в «Жёсткие правила агентства» и «Группы внутри кампании», применяется как есть (Поиск/РСЯ раздельно, тест-матрица 3-5 объявлений).
- В `05_campaign_structure.json` корень получает `"ad_model": "classic"`.

## Жёсткие правила агентства

### 1. Поиск vs РСЯ — всегда отдельные кампании

Никогда не смешивай Поиск и РСЯ в одной кампании. Это две разные модели:
- **Поиск** — пользователь ввёл запрос, оценивает варианты.
- **РСЯ** — пользователь просматривает сайт по теме, мы догоняем.

CTR, CPC, тексты, стратегии торгов — разные. В одной кампании их нельзя сравнивать и нельзя оптимизировать.

### 2. Один угол отстройки = одна кампания на Поиске

Если в брифе указано 2-3 сужающих слова (`+премиум`, `+срочно`, `+межгород`) — это 2-3 разные кампании, не одна. Зачем:

- Кросс-минусация работает только на уровне кампаний.
- Тексты под «премиум» и «срочно» — разные.
- Бюджет на каждую кампанию управляется отдельно — можно сразу остановить ту, что не идёт.

Если все ключи под одно сужающее — одна кампания, без вопросов.

### 3. ВЧ — отдельная группа (или отдельная кампания)

Если в `04_keys_search_vch.csv` есть ключи (т.е. ВЧ разрешены — бюджет ≥100к + массовый продукт + бренд), они идут в **отдельную группу** того же угла. Зачем:

- ВЧ съедают бюджет быстро, нужен отдельный контроль.
- Маркетолог в любой момент может выключить только ВЧ-группу.
- Конверсии случайные, статистика отдельная.

При очень большом бюджете (≥200к) — ВЧ выносим в **отдельную кампанию**, не группу.

### 4. B2B-сегменты — отдельная кампания

Если в семантике видны B2B-намерения (`+оптом`, `+длябизнеса`, `+корпоративный`) — это отдельная кампания со своими объявлениями (другой tone of voice) и метрикой (B2B-цель в Метрике).

### 5. Брендовая — отдельно

Если у клиента узнаваемый бренд — отдельная **«Брендовая»** кампания только с брендированными ключами (`<бренд> + продукт`, `<бренд> отзывы`, `<бренд> цена`). Эта кампания почти всегда самая дешёвая по CPC и самая конверсионная — нельзя её мешать с категорийными ключами.

### 6. РСЯ — отдельной кампанией со своими группами

Все РСЯ-ключи (из `04_keys_rsya.csv`) идут в отдельную кампанию (или несколько, если углов несколько). Внутри — группировка по углам: «РСЯ-Премиум», «РСЯ-Срочно», или одна общая группа если ключи перемешаны.

### 7. Ретаргет — отдельная кампания

Если в брифе предусмотрен ретаргет — он живёт в отдельной кампании. Условие — настроенные сегменты Метрики (см. `metrika-goals-setup.md`).

## Группы внутри кампании

Внутри одной кампании ключи группируем по правилу **«один лендинг + однородные ключи + одно объявление»**:

- **Один лендинг на группу.** Если ключи ведут на разные страницы — разные группы.
- **10-30 ключей на группу.** Меньше — мало статистики для теста объявлений. Больше — теряется однородность.
- **3-5 объявлений на группу.** Тестовая матрица (см. `ad-copywriting.md`).
- **Группа = одно сообщение.** Все ключи группы должны хорошо ложиться под один и тот же заголовок объявления.

## Алгоритм построения структуры

### Шаг 1. Собрать сужающие слова из брифа

Из `00_brief.md` поле 7. Например:
- УТП: премиум-сегмент
- Сужающие: `+премиум`, `+элитный`, `+авторский`

### Шаг 2. Раскидать ключи Шага 4 по сужающим

Для каждого ключа из `04_keys_search_obligatory.csv` смотрим, какое сужающее в нём — это кампания. Если ни одного — кладём в **общую кампанию** «<slug>-Поиск-General» (но обычно таких быть не должно — фильтр Шага 4 уже отсёк).

### Шаг 3. Внутри кампании сгруппировать по лендингам

Если у продукта один лендинг — одна группа на всю кампанию.
Если несколько (например, разные страницы под разные сегменты) — отдельная группа на каждый.

### Шаг 4. ВЧ в отдельную группу

Все ключи из `04_keys_search_vch.csv` — в отдельную группу той же кампании.

### Шаг 5. РСЯ-кампания(и) аналогично

Кампанию (одну или несколько) для РСЯ строим по тем же сужающим словам, ключи из `04_keys_rsya.csv`.

## Особые случаи

### Один угол отстройки

Одна Поиск-кампания (всё в ней). РСЯ-кампания отдельно. Кросс-минусация не нужна — некого минусовать.

### Много кампаний — мягкая подсказка (потолка нет)

**Жёсткого лимита на число кампаний в запуске нет** — их столько, сколько углов / сегментов / лендингов. Если кампаний много и близкие по смыслу — это не запрет, а повод переспросить: «получилось {N} кампаний; пара углов близки (+премиум и +авторский). Оставляем раздельно или объединяем?» Маркетолог решает; при отказе объединять — оставляем как есть.

### Очень маленький бюджет (<30к)

Не дробим. Одна Поиск-кампания + при необходимости одна РСЯ. Иначе на каждую <10к — статистики не наберём.

### Очень большой бюджет (>200к)

Дробим обстоятельно:
- Поиск по углам (отдельная кампания на каждый)
- Поиск ВЧ отдельной кампанией (не группой)
- РСЯ по углам (отдельная кампания на каждый угол)
- Ретаргет отдельной кампанией (3-5 сегментов Метрики)
- Брендовая отдельно
- B2B (если есть) отдельной кампанией

10+ кампаний — норма для бюджета 300к+.

### Срочный спрос

Один угол на одну кампанию. РСЯ — обычно не используем (пользователь не «прогревается»). Брендовая — только если бренд реально узнаваемый, иначе пропускаем.

### Премиум

ВЧ почти всегда нет → только НЧ+СЧ. РСЯ — основной канал, не Поиск. Структура часто: 1-2 Поиск-кампании + 2-3 РСЯ-кампании (по углам).

### B2B SaaS

Минимум 2 кампании: «Категорийный поиск» (`+crm`, `+erp`) + «Сегментный поиск» (`+crm +для салонов`). По возможности — «Альтернатива конкурентам» (`+yclients +альтернатива`) отдельной кампанией.

## Стиль работы

- **Структура — не «как попроще», а «как правильно».** Маркетологу проще одна кампания, но через 2 недели нечего будет оптимизировать.
- **Сужающие слова из брифа — закон.** Не объединяем угла, не выдумываем новые.
- **Не множь сущности.** Если 2 группы с почти одинаковыми ключами — это одна группа.
- **Имена кампаний — по шаблону.** `<slug>-<Type>-<Narrowing>` — единый формат для всех проектов агентства.

## Связи в пайплайне
