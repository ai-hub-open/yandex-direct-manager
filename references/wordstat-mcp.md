# Wordstat через MCP `yandex-wordstat` — частотности и сбор семантики

**Основной путь для Шагов 1 и 3.** Хостовый сервер `https://wordstat-mcp.aihub.click.ru/mcp` отдаёт статистику поискового спроса Яндекса (под капотом — Yandex Cloud Search API, Wordstat `topRequests`). Фолбеки, если MCP нет: `scripts/wordstat_api.py` (свой ключ Cloud) → браузерный пробив (`wordstat-browser.md`) → список от маркетолога. Порядок не менять.

## Подключение

- Имя сервера в конфиге клиента: `yandex-wordstat`. Инструменты ищи по серверу и смыслу (`top requests`, `regions`, `dynamics`), а не по жёсткому имени — см. «Инструменты» ниже.
- Авторизация: **API-токен click.ru** в заголовке `Authorization: Bearer <токен>` (шлюз принимает и `X-Auth-Token`). Токен — профиль https://click.ru/userinfo.html → «API Token». Свой ключ Yandex Cloud (`WORDSTAT_API_KEY`/`WORDSTAT_FOLDER_ID`) для MCP **не нужен** — он на стороне сервера.
- Подключение делает `scripts/setup_yandex_direct_mcp.py --server both` (по умолчанию ставит вместе с `yandex-direct`) — см. `docs/hosted-mcp-setup.md` репозитория пакета.
- Без токена сервер отвечает `401`; с недействительным — `401 click.ru: токен недействителен`.

## Инструменты

Точный список смотри в сессии (список инструментов сервера `yandex-wordstat`) — он источник правды. Подтверждённый набор возможностей соответствует Cloud Search API Wordstat:

| Задача | Ожидаемый инструмент | Что возвращает |
|---|---|---|
| Частотность фразы + похожие запросы + ассоциации | `top_requests` (или близкое имя) | `results[]` (запросы, содержащие фразу, с count), `associations[]` (семантически близкие), `totalCount` — всё за последние 30 дней |
| Спрос по регионам | `regions` | `count`, `share`, `affinityIndex` (>100% — интерес выше среднего) |
| Сезонность | `dynamics` | Ряд `{date, count, share}` по дням/неделям/месяцам |
| Справочник регионов | `list_regions` | Дерево «id → название» (213 — Москва, 2 — СПб) |

Особенности API, которые надо учитывать при разборе ответов:

- Количественные поля могут приходить **строками** — кастуй в число.
- Операторы Wordstat (`!`, `+`, `[]`, `"`) в запросах **не поддерживаются** — фразы шли «как есть».
- Один вызов = одна фраза. Лимит ~5–10 rps: при цикле по фразам держи паузу ≥0.2 с и не долби повторами при 429.
- Справочник регионов статичен — запроси один раз и кэшируй на сессию.

## Шаг 1: частотности масок

Для каждой рабочей маски из `01_masks.json` вызови инструмент частотностей с `regionIds` из брифа. Запиши `totalCount` (или суммарную частотность по `results`, если `totalCount` нет) в `frequency` маски; лог итераций — `01_masks_wordstat_log.md`. Отсев ниже порога 150 показов/мес — как раньше.

## Шаг 3: рекурсивный сбор семантики волнами

Выполняет субагент `semantics` (или оркестратор инлайн, если субагентов нет). Алгоритм тот же, что у `scripts/wordstat_api --mode semantics`, но цикл крутит агент через MCP:

1. Семена волны 0 — `_masks_seed.txt` (узкие комбинации масок **плюс широкие одиночные слова продукта**).
2. На каждое семя — вызов инструмента частотностей (`numPhrases` до 300, `regionIds` из брифа). В сбор идут и `results`, и `associations`.
3. Дедупликация по нормализованной форме (lowercase, trim).
4. Запрос становится семенем следующей волны, только если содержит **якорь** из `_anchors.txt` и прошёл порог семени (10 показов/мес).
5. **Каждую волну дописывай в `03_semantics_raw.csv`** (столбцы `keyword,frequency,mask_parent,source,depth`; `source` = result/association, `depth` = номер волны). В чат — одна строка итога на волну, не сырьё.
6. Стоп — по первому из предохранителей профиля:
   - **«Стандарт» (дефолт):** глубина ≤2, ≤150 семян на волну, стоп при <5% новых в волне, ≤1000 вызовов, ≤15 минут.
   - **«Глубокий»** (если суммарной частотности не хватает до необходимой из `02_frequency.json`): глубина ≤3, ≤300 семян, стоп при <3% новых, ≤5000 вызовов, ≤40 минут.
7. В конце зафиксируй для сводки: причину остановки, число вызовов, число волн, собрано ключей, суммарную частотность.

Если у сервера есть batch-инструмент (несколько фраз за вызов) — используй его вместо цикла, это дешевле.

**Про расход контекста:** тысячи ключей в чат не выводим никогда — только файлы и сводка ≤20 строк (формат — в `subagents/semantics.md`).

## Если MCP недоступен

1. `scripts/wordstat_api.py --check` — если есть ключ Cloud (`WORDSTAT_API_KEY` + `WORDSTAT_FOLDER_ID`), шаги 1 и 3 идут готовым скриптом (та же логика волн, `--mode masks` / `--mode semantics`).
2. Нет и ключа — браузерный пробив частотностей (`wordstat-browser.md`), делает оркестратор.
3. Нет и браузера — список от маркетолога, `frequency: n/a`, пометка о пропуске по формату из раздела «Что нужно от среды» корневого `SKILL.md`.

Любой переход на фолбек фиксируй пометкой о пропуске в артефакте шага и в сводном разделе `10_launch_log.md`.
