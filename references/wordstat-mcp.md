# Wordstat через MCP `yandex-wordstat` — частотности и сбор семантики

**Основной путь пробива частотностей для Шагов 1 и 3.** Хостовый сервер `https://wordstat-mcp.aihub.click.ru/mcp` — шлюз click.ru поверх Вордстата; отдаёт число показов в месяц по списку фраз. **Расширение семантики он не делает** (см. «Шаг 3»). Фолбеки на пробив, если MCP нет: `scripts/wordstat_api.py` (свой ключ Cloud) → браузерный пробив (`wordstat-browser.md`) → список от маркетолога. Порядок не менять.

## Подключение

- Имя сервера в конфиге клиента: `yandex-wordstat`. Инструменты ищи по серверу и смыслу (частотность фразы пачкой), а не по жёсткому имени — см. «Инструменты» ниже.
- Авторизация: **API-токен click.ru** в заголовке `Authorization: Bearer <токен>` (шлюз принимает и `X-Auth-Token`). Токен — профиль https://click.ru/userinfo.html → «API Token». Свой ключ Yandex Cloud (`WORDSTAT_API_KEY`/`WORDSTAT_FOLDER_ID`) для MCP **не нужен** — он на стороне сервера.
- Подключение делает `scripts/setup_yandex_direct_mcp.py --server both` (по умолчанию ставит вместе с `yandex-direct`) — см. `docs/hosted-mcp-setup.md` репозитория пакета.
- Без токена сервер отвечает `401`; с недействительным — `401 click.ru: токен недействителен`.

## Инструменты

Точный список смотри в сессии (список инструментов сервера `yandex-wordstat`) — он источник правды. Реальный инвентарь (сверено живьём 26.08.2026) — три инструмента, только частотности:

| Инструмент | Что делает | Параметры |
|---|---|---|
| `wordstat_shows_batch` | Частотность пачкой, **синхронно**. Возвращает `{ result: [{keyword, error, stat, cache_date}], total, pending }` | `keywords` (до **1000** за вызов), `region_id` (int, дефолт 213), `strict` (bool — оператор `!` на каждое слово) |
| `wordstat_shows_batch_submit` | То же асинхронно: возвращает `{id, status:"pending"}` | те же |
| `wordstat_shows_batch_status` | Забрать результат по `id`; `status`: `pending` / `done` / `failed` | `id` |

**Чего на сервере нет:** инструментов «похожие запросы», «спрос по регионам», «динамика/сезонность», «справочник регионов». **Нет полей** «список найденных запросов», «ассоциации», «суммарный счётчик показов». Есть только `stat` — показов/мес по каждой присланной фразе.

### Особенности API

- `region_id` — **одно число**, не список (213 — Москва, 1 — Москва и область, 2 — СПб, 225 — Россия). Нужны несколько регионов — несколько вызовов.
- `strict: true` вешает оператор `!` на каждое слово (точная словоформа). По умолчанию `false` — широкое соответствие, как в интерфейсе Вордстата.
- В элементе ответа: `error: 0` — готово, `stat` — показов/мес (`0` — валидное значение, не ошибка), `error: 110` — ещё считается. `cache_date` — дата кэша.
- **До 1000 фраз за вызов.** Цикл по одной фразе не нужен и вреден.
- Больших пачек не бойся, но при таймаутах клиента используй асинхронную пару `wordstat_shows_batch_submit` → `wordstat_shows_batch_status`.
- **Шлюз периодически отдаёт `gateway 502 ... upstream EOF`.** Правило: один повтор тем же телом через 5 с, при втором отказе — режь пачку пополам, при третьем — уходи на фолбек и ставь пометку о пропуске. Не долби повторами. Подробнее — `yandex-direct-mcp.md` → «Сбои шлюза».

## Шаг 1: частотности масок

Собери все рабочие маски из `01_masks.json` в **один** список и отправь одним вызовом `wordstat_shows_batch({ keywords: [...], region_id: <из брифа> })`. Масок обычно 7–30 — это один вызов, а не 30.

`stat` каждого элемента → поле `frequency` соответствующей маски. Элементы с `error: 110` добери повторным вызовом только по ним. Лог — `01_masks_wordstat_log.md`. Отсев ниже порога 150 показов/мес — как раньше.

Регионов в брифе несколько — вызов на каждый `region_id`, частотности суммируй и зафиксируй в логе, по каким регионам считалось.

## Шаг 3: расширение семантики

⚠️ **Сервер `yandex-wordstat` не расширяет семантику.** Он отвечает «сколько показов у этой фразы», но не «какие ещё запросы бывают». Рекурсивные волны, которые питались полем `results`, через MCP невыполнимы. Расширение берётся из одного из источников ниже, а MCP **пробивает частотности готового списка**.

### Путь 1 (предпочтительный): скрипт Cloud Search API

Есть ключ `WORDSTAT_API_KEY` + `WORDSTAT_FOLDER_ID` и запуск кода — это единственный путь, который даёт настоящую рекурсию с ассоциациями:

```
python -m scripts.wordstat_api --mode semantics \
    --phrases-file direct-campaigns/<slug>/_masks_seed.txt \
    --anchors-file direct-campaigns/<slug>/_anchors.txt \
    --regions <из брифа> \
    --output direct-campaigns/<slug>/03_semantics_raw.csv
```

Профили «Стандарт» / «Глубокий» — как раньше, флагами.

### Путь 2: комбинаторная генерация + пакетный пробив (когда есть только MCP)

1. **Сгенерируй кандидатов** из `01_masks.json` перемножением:
   колонка Б (продуктовые слова + синонимы + товарозаменители)
   × колонка А (сужающие)
   × модификаторы намерения (`купить`, `цена`, `заказать`, `с доставкой`, `недорого`, `отзывы`, `рядом`, `на заказ`, `<город>` из брифа)
   × словоформы (ед./мн. число, основные падежи).
   Держись в пределах 300–1000 кандидатов — это ровно один-два вызова.
2. **Пробей пачкой:** `wordstat_shows_batch({ keywords: [...до 1000...], region_id: ... })`.
3. **Отсей** `stat < 150` в `04_keys_excluded.csv` с причиной `below_threshold`.
4. **Одна волна углубления:** возьми выжившие фразы с `stat ≥ 10`, добавь к ним недостающие модификаторы и словоформы, пробей второй пачкой. Больше двух волн смысла не имеет — новые слова из воздуха не берутся.
5. Пиши в `03_semantics_raw.csv` со столбцами `keyword,frequency,mask_parent,source,depth`, где `source = combinatorial`, `depth` = номер пачки.

🚫 **Категорически нельзя** дописывать в `03_semantics_raw.csv` фразы, которые не были пробиты, и проставлять им выдуманную частотность. Не пробита — либо `frequency: n/a` с пометкой, либо не попадает в файл вовсе.

**Обязательная пометка о пропуске** в `03_semantics_raw.csv` и в сводке Шага 3:

> ⚠️ **пропущено: нет расширения семантики через Вордстат** — сервер `yandex-wordstat` умеет только частотности, ассоциации и похожие запросы не собирались; ядро построено комбинаторикой масок и пробито пакетно. Потеряно: длинный хвост НЧ-запросов, которые не выводятся из масок. Как добрать: прогнать `scripts/wordstat_api.py --mode semantics` с ключом Yandex Cloud или выгрузить ядро сторонним сервисом и прислать списком.

## Если MCP недоступен

1. `scripts/wordstat_api.py --check` — если есть ключ Cloud (`WORDSTAT_API_KEY` + `WORDSTAT_FOLDER_ID`), шаги 1 и 3 идут готовым скриптом (та же логика волн, `--mode masks` / `--mode semantics`).
2. Нет и ключа — браузерный пробив частотностей (`wordstat-browser.md`), делает оркестратор.
3. Нет и браузера — список от маркетолога, `frequency: n/a`, пометка о пропуске по формату из раздела «Что нужно от среды» корневого `SKILL.md`.

Любой переход на фолбек фиксируй пометкой о пропуске в артефакте шага и в сводном разделе `10_launch_log.md`.
