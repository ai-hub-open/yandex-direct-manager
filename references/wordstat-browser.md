# Wordstat через браузер — пробив частотностей под сессией пользователя

Используется на **Шаге 1** (частотности масок) и **Шаге 3** (семантика) как **фолбек, когда нет ключа Cloud Search API** (`WORDSTAT_API_KEY`/`WORDSTAT_FOLDER_ID`). Раньше на этом месте был режим симуляции `[SIM]` с прикидочными числами — теперь вместо прикидки **реально пробиваем частотности через браузер пользователя**.

## Когда применять

- `python -m scripts.wordstat_api --check` упал или ключа нет **и** у пользователя есть залогиненный Яндекс в Chrome с доступом к https://wordstat.yandex.ru.
- Приоритет источников частотности не меняется: **Cloud Search API → браузерный пробив → ручной сбор/сторонние сервисы**. Браузер — честная замена прикидке, а не замена API.

## Где выполняется

**Только в оркестраторе** (основной контекст), потому что инструмент управления браузером пользователя (например, `claude-in-chrome`) живёт там. Субагент `semantics` (форк) браузер не видит — если API недоступен, он не может пробить сам; пробив делает оркестратор до/после делегирования либо инлайн-ветвью Шагов 3–4.

**Если в среде нет и браузерного инструмента** — этот путь целиком недоступен: частотности остаются `frequency: n/a`, семантику присылает маркетолог списком, и шаг получает пометку о пропуске (формат — в разделе «Что нужно от среды» корневого `SKILL.md`). Прикидку вместо частотности не подставляем ни при каких условиях.

## Честная граница метода

- Браузер даёт **реальные «показов в месяц»** по **обозримому списку** фраз (маски Шага 1, курируемый список ключей Шага 3): десятки–сотни ручных запросов.
- **Тысячные рекурсивные волны** (ассоциации + углубление, как в `scripts.wordstat_api --mode semantics`) через браузер непрактичны — это работа для API. Без API семантику собирает пользователь (руками/сторонним сервисом), а браузер **пробивает частотности** уже собранного списка и отсекает мусор ниже порога.

## Процедура

1. Открой новую вкладку и перейди на https://wordstat.yandex.ru (сессия и логин — пользователя; если разлогинен, попроси залогиниться сам через `! ...` или в браузере).
2. Выстави **регион** из брифа (виджет региона над строкой запроса) — частотность считается по региону, дефолтная «вся Россия» исказит прогноз.
3. Для каждой фразы: ввести фразу → прочитать число **«показов в месяц»** у самой фразы (верхняя строка отчёта), а не сумму вложенных запросов.
4. При пробиве масок (Шаг 1) фиксируй частотность в `01_masks.json` / лог `01_masks_wordstat_log.md`. При пробиве ключей (Шаг 3/4) — в `03_semantics_raw.csv` (столбец `frequency`).
5. Отсекай по порогам Шага 4 (минимум 150 показов/мес; НЧ<350/СЧ 350–750/ВЧ>750).

## Осторожность

- **Капча и лимит темпа.** Частые автоматические запросы Вордстат банит капчей. Держи умеренный темп, при капче — пауза и решение капчи пользователем; не долби подряд.
- **Кавычки/операторы.** Для точной частотности фразы используй оператор `"..."` (фразовое соответствие) — иначе число завышено широкими вложениями.
- **Регион не сбрасывай** между фразами — Вордстат иногда возвращает регион к дефолту после навигации, перепроверяй.
- **Не выдумывай числа.** Если фразу пробить не удалось (капча, недоступность) — помечай `frequency: n/a`, а не подставляй прикидку. В артефакт пиши, сколько фраз реально пробито.

## Артефакты

Те же, что у API-пути: частотности попадают в `01_masks.json` (Шаг 1) и `03_semantics_raw.csv` (Шаг 3). В лог добавь пометку `source: browser` и число пробитых/непробитых фраз, чтобы на гейте было видно покрытие.
