# Wordstat Filter — фильтрация семантики по частотности и каналам

Используется на Шаге 4 пайплайна (между полным сбором семантики и структурой кампаний). Задача — **превратить сырой список «ключ + частотность» в структурированные группы для Поиска и РСЯ**, по правилам агентства.

«Фильтр» — название условное. Мы ничего не выбрасываем без явного решения; мы **сортируем и помечаем**.

## Главный принцип

В Директе **низкочастотники работают лучше высокочастотников** для большинства проектов: меньше конкуренция, ниже цена клика, выше конверсия. Это контр-интуитивно для новичков, поэтому пороги и распределение — **жёсткие правила**, не рекомендации.

## Пороги агентства (внутренние)

| Тип | Показы/мес |
|-----|------------|
| **НЧ** (низкочастотники) | < 350 |
| **СЧ** (среднечастотники) | 350 – 750 |
| **ВЧ** (высокочастотники) | > 750 |

Минимальный порог отдельного запроса — **150 показов/мес** (ниже — шум, в работу не берём). Это правило агентства, строже стандартного «всё что есть в Wordstat».

## Правила распределения по каналам

### Поиск

- **НЧ + СЧ — обязательно на любом проекте.** База кампаний, основной поток заявок.
- **ВЧ — только в отдельной группе** и только если выполнены ВСЕ три условия:
  1. Бюджет ≥ 100 000 ₽/мес для одного гео.
  2. Продукт массовый (тираж, оборачиваемость, стандарт цены).
  3. Есть узнаваемый бренд (или клиент готов вкладывать в брендинг).

Если хоть одно НЕТ — **не лить ВЧ на поиск**. Маркетологу прямо: «ВЧ съест бюджет за 3 дня, статистики не наберём, конверсии случайные».

### РСЯ

- **СЧ — основа.** Большинство ключей РСЯ — отсюда.
- **ВЧ можно добавлять**, но не как основу — для расширения охвата на этапах прогрева.
- **НЧ почти не берём.** Wordstat-частотность <350 в РСЯ часто значит «алгоритм не найдёт пользователя» — таргетинг плавает, бюджет сольётся.

### Если бюджет 50/50 Поиск+РСЯ
Это и есть оптимум для большинства — Поиск собирает горячий спрос, РСЯ догревает и приводит новых. Скилл распределяет ключи по правилам выше.

### Если только Поиск (срочный спрос)
Эвакуатор, такси, аварийный сантехник: в РСЯ незачем — пользователь не «прогревается», он ищет здесь и сейчас. Весь бюджет в Поиск, ВЧ всё равно осторожно.

### Если только РСЯ
Редко, но бывает (новый продукт, никто не ищет — формируем спрос). НЧ оставляем единичные с точным таргетингом, основа — СЧ+ВЧ.

## Вход

1. **Собранная семантика** — `03_semantics_raw.csv` с колонками `keyword`, `frequency`, `mask_parent` (Шаг 3).
2. **Контекст канала** — Поиск / РСЯ / оба. Из `00_brief.md` (поле 5).
3. **Бюджет на канал** — для решения по ВЧ. Из `02_frequency.json` или `00_brief.md` (поля 4-5).
4. **Тип ниши** — обычная / срочный спрос / премиум / B2B SaaS. Определяется по контексту брифа.
5. (опц.) **Сужающие слова** — из `00_brief.md` (поле 7), для распределения ключей по будущим кампаниям.

Если входа нет:
```
1. Где собранная семантика? (путь к файлу или вставь CSV)
2. Кампании планируем: только Поиск / только РСЯ / оба?
3. Бюджет на канал: ?
4. Тип ниши: обычная / срочная / B2B / премиум?
```

## Фаза 1. Сортировка по порогам

1. Каждый ключ помечаем `freq_tier`: `НЧ` / `СЧ` / `ВЧ` / `ниже 150 (отбрасываем)`.
2. Сразу отделяем «нулевые» (frequency=0 или null — маска не существует).
3. Считаем суммарную частотность каждой группы (сравниваем с `02_frequency.json`).

## Фаза 2. Распределение по каналам (три прохода)

**Проход 1 — Поиск (обязательная база).** Все НЧ и СЧ → `04_keys_search_obligatory.csv`. Помечаем группу = сужающее слово (`mask_parent` из Шага 3).

**Проход 2 — Поиск (ВЧ, опционально).** Проверяем три условия (бюджет ≥100к, массовый продукт, бренд). Все три ДА — выделяем ВЧ в `04_keys_search_vch.csv` как отдельную будущую группу с пометкой «контроль конверсий, отключать быстро». Хоть одно НЕТ — в `04_keys_excluded.csv` со статусом `vch_no_budget` / `vch_not_mass_market` / `vch_no_brand`.

**Проход 3 — РСЯ.** СЧ и ВЧ → `04_keys_rsya.csv`. НЧ → `04_keys_excluded.csv` со статусом `nch_rsya_too_narrow`, за исключением 1-3 самых таргетированных (пометка «возможно ручное добавление позже»).

## Артефакты

В рабочей папке:

- `04_keys_search_obligatory.csv` — НЧ + СЧ для Поиска (база)
- `04_keys_search_vch.csv` — ВЧ для Поиска (только если выполнены 3 условия)
- `04_keys_rsya.csv` — СЧ + ВЧ для РСЯ
- `04_keys_excluded.csv` — отброшенные с причиной (статус)
- `04_wordstat_filter_summary.md` — отчёт для маркетолога

Структура каждого CSV:
```
keyword,frequency,freq_tier,group,channel,status,notes
```

## Гейт с маркетологом

Сводка 6-8 строк:

```
ВЧ: 12 ключей (сумма 24 500 показов)
СЧ: 47 ключей (сумма 18 200 показов)
НЧ: 213 ключей (сумма 31 400 показов)
Ниже порога 150: 89 — отбросили
Нет в Wordstat: 14 — отбросили

Поиск (обязательная база НЧ+СЧ): 260 ключей, 49 600 показов/мес
Поиск (ВЧ отдельная группа): 0 ключей — бюджет 50к не дотягивает до 100к минимума
РСЯ (СЧ+ВЧ): 59 ключей, 42 700 показов/мес
```

Прямой вопрос: **«Подходит распределение? Какие группы корректируем? Передаю в структуру кампаний?»**

Если маркетолог хочет отступить от правил («всё-таки залей ВЧ на поиск на пробу») — фиксируем в `04_wordstat_filter_summary.md` как «решение маркетолога, отступление от правил агентства» и идём дальше.

## Особые правила по нишам

Надстраиваются над общими порогами на Фазе 3.

### Срочный спрос (active demand)

**Признаки:** эвакуатор, такси, аварийный сантехник, заклинило замок, прорвало трубу, ветеринар скорая.

1. **Только Поиск.** РСЯ не имеет смысла — пользователь не «прогревается».
2. **НЧ-сценарные — ДА. НЧ-локальные — НЕТ.**
   - `+эвакуатор +послеДТП +Казань` (~80/мес) — берём, конверсионный сценарий.
   - `+эвакуатор +улицаЧугунная +Казань` (~60/мес) — отбрасываем (улиц тысячи). Помечай `nch_urgent_too_narrow`.
3. **ВЧ — почти всегда нет.** Срочный спрос редко с большим бюджетом. Даже если бюджет позволяет — ВЧ `+эвакуатор` даёт огромный CTR, но плохие конверсии («а сколько стоит?» с отказом).
4. **СЧ — основная база.** `+эвакуатор +срочно +Казань` (300-500/мес) — то, на чём строится кампания.
5. Если в Москве `+эвакуатор` 8000 показов — это не сигнал «ВЧ можно», это просто высокая конкуренция и аукцион.

### Премиум-сегмент

**Признаки:** авторская живопись, элитная недвижимость, luxury-часы, дизайнерская одежда, путешествия.

1. **80% масок будут НЧ — это норма.** Не «провал», специфика ниши.
2. **Экономика держится на чеке.** При среднем чеке 50к+ ₽ и марже 40% даже 50 запросов в месяц с конверсией 1% дают окупаемую кампанию.
3. **СЧ с lifestyle-маркерами** (`+премиум +часы`, `+эксклюзив +авто`) — золотой фонд. Если их 10-15 — это много.
4. **ВЧ без сужающих** (`часы`, `недвижимость`) — НЕ брать. Аукцион проиграем агрегаторам.
5. **РСЯ — да, активно.** Премиум часто покупает после долгого прогрева. РСЯ + ретаргет — основной канал поверх Поиска.
6. **Не предлагай «расширить НЧ»** — это путь в массовый сегмент, потеряем позиционирование.

### B2B SaaS

**Признаки:** CRM, ERP, бухучёт, чат-боты, аналитика, онлайн-кассы.

1. **Категорийные ВЧ** (`crm для салона красоты`) — берём на Поиск **в отдельную группу**. Исключение из правила «без бренда не лить»: B2B-категория сама себя сегментирует.
2. **Сегментные НЧ** (`crm для самозанятого парикмахера`) — основная база Поиска. Маленький объём, но высокая конверсия и LTV.
3. **Альтернатива-конкуренту** (`yclients альтернатива`, `аналог dikidi`) — отдельная группа Поиска, обычно СЧ, очень тёплый.
4. **РСЯ — обязательно с look-alike** на текущих клиентов. СЧ-категорийные + LAL.
5. **Не сливать ВЧ-non-branded в РСЯ** (`сайт для записи клиентов` без `crm`) — ловушка, ведущая на агрегаторы и форумы.

### Локальные услуги (массовый сформированный спрос)

**Признаки:** доставка пиццы, ремонт телефонов, уборка квартир, химчистка.

1. **ВЧ + локация** (`доставка пиццы Москва`) — берём, но в отдельную группу с жёстким минусованием по районам, где не работаем.
2. **НЧ + локация районная** (`доставка пиццы Чертаново`) — основа. Низкая конкуренция, дешёвый клик.
3. **СЧ + категорийный** (`ремонт айфон срочно`) — стандартная группа Поиска.
4. **РСЯ — крайне осторожно.** Массовый сегмент в РСЯ часто пересекается с Avito, Profi.ru — не выигрывается.

### Сезонные товары

**Признаки:** новогодние подарки, цветы 14 февраля, школьные товары к сентябрю.

1. **Вне сезона:** ничего не запускать или резко минимальный бюджет на ретаргет.
2. **В сезон:** все правила выше переключаются — даже ВЧ становятся релевантными, аукцион ёмкий, конверсия высокая. Маркетолог должен указать «сейчас сезон».
3. Дополнительно — корректировки на даты пика (см. `frequency-calculator.md`).

### Default — ничего не подходит

1. Применяй общие правила без корректировок.
2. Помечай: `niche_rules: default`.
3. На гейт быстрее — маркетолог корректирует.

## Стиль работы

- **Цифры, не предположения.** Каждое решение по ключу основано на frequency и правилах.
- **Помечать, а не выбрасывать.** Любой отброшенный — со статусом. Маркетолог может вернуть.
- **Объяснять отказ от ВЧ.** Без обоснования маркетолог думает, что мы зажимаем трафик.
- **Не паниковать на 80% НЧ в премиуме/B2B.** Норма. Объясняем, что экономика на чеке, не на охвате.
