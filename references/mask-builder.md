# Mask Builder — матрица плюс-слов для семантики

Используется на Шаге 1 пайплайна (после брифа, перед прогнозом частотности). Задача — превратить **УТП и сужающие слова из брифа** в **структурированную матрицу плюс-слов (масок)**, готовых к подаче в Yandex Cloud Wordstat API.

«Маска» = обязательное плюс-слово (`+премиум`, `+ручной`, `+срочно`), которое должно входить в каждый запрос определённой группы. Без масок сбор семантики уходит в Wildberries и общий «ширпотреб» — мы хотим оставаться внутри угла отстройки.

## Главный принцип — методология агентства: две колонки

Не «список ключевых слов», не «семантическое ядро» — именно **две колонки**:

- **Колонка А (сужающие слова)** — определяет угол отстройки: премиум / ручной работы / срочно / межгород / самозанятых.
- **Колонка Б (общие слова продукта)** — то, что реально вводят в поиск: картины / эвакуатор / CRM / маникюр.

Финальный запрос = одно сужающее × одно общее (`+премиум +картины`, `+срочно +эвакуатор`). Расширяя обе колонки синонимами, получаем все варианты, как один продукт могут искать разные люди.

## Вход (обязателен)

Скилл **не запускается без сужающих слов**. Если их нет в брифе — задай один прямой вопрос маркетологу: «Какие 1-3 слова определяют ваш угол отстройки (например: премиум, срочно, для самозанятых, межгород)?»

1. **`00_brief.md`** — поле 7 (УТП + сужающие слова) и поле 1 (продукт, для колонки Б).
2. **Контекст продукта** — название, регион, тип спроса (определяется по полю 7 и полю 1).
3. **Доступ к Wordstat** — основной путь: MCP `yandex-wordstat` (`references/wordstat-mcp.md`). Фолбек: Yandex Cloud Search API напрямую, env `WORDSTAT_API_KEY` + `WORDSTAT_FOLDER_ID`, клиент `scripts/wordstat_api.py` (https://yandex.cloud/ru/docs/search-api/concepts/wordstat). Если нет ни MCP, ни ключа — частотности пробиваются через браузер пользователя (`references/wordstat-browser.md`).

## Фаза 1. Распознавание типа спроса

Определи тип ниши (это влияет на шаблон масок). См. «Шаблоны масок по типу спроса» ниже.

- **Срочный спрос** (эвакуатор, такси, заклинило замок): сужающие = сценарии и срочность.
- **B2B SaaS** (CRM, ERP): сужающие = сегмент покупателя или альтернатива конкуренту.
- **Премиум-сегмент** (luxury): сужающие = lifestyle-маркеры.
- **Ручная работа / на заказ** (картины, мебель): сужающие = метод изготовления.
- **Массовый сформированный спрос** (доставка пиццы, ремонт): сужающие = район/гарантия/срок.

Если ниша не попадает ни в один шаблон явно — действуй по дефолту (сужающие из брифа + общие из продукта + товарозаменители), помечай «шаблон не подошёл, по умолчанию».

## Фаза 2. Первая матрица (минимальная, без синонимов)

Цель — показать маркетологу **направление**.

1. **Колонка А.** Ровно те сужающие, что в брифе. Не добавляем новые.
2. **Колонка Б.** Из контекста — 2-4 базовых слова. Для картин: `картины`. Если в нише очевидные товарозаменители — добавь 1-2 (`картины` + `панно`), но не углубляйся.
3. **Финальные комбинации.** Декартово произведение А × Б — черновик для маркетолога.

`masks_matrix.md` сохраняем как драфт.

Покажи маркетологу:

|----------------|------------------|
| +премиум       | картины          |

## Фаза 4. Расширение синонимами + Wordstat

### 4.1 Языковые синонимы (для обеих колонок)

**Точные смысловые эквиваленты**, не родственные понятия:
- `+премиум` → `+элитный`, `+эксклюзивный`, `+luxury`, `+премиальный`, `+vip`
- `+ручной` → `+ручнойработы`, `+руками`, `+handmade`, `+авторский`

### 4.2 Смысловые синонимы / товарозаменители

**Другое название того же класса** или **близкий продукт-заменитель**:
- `картины` ↔ `панно` ↔ `постеры авторские` ↔ `холсты` ↔ `гобелены`
- `эвакуатор` ↔ `буксировщик` ↔ `тягач`
- `CRM` ↔ `программа учёта` ↔ `система записи` ↔ `онлайн-журнал`
- `маникюр` ↔ `ногтевой сервис` ↔ `nail`

Это даёт семантику, которую легко пропустить: человек ищет «панно ручной работы», а мы льём только на «картины» — мимо.

### 4.3 Итеративный заход в Wordstat

**Основной путь — MCP `yandex-wordstat`** (`references/wordstat-mcp.md`): для каждой из 7-10 перспективных комбинаций расширенной матрицы (не всё подряд — бережём квоту) вызови инструмент частотностей с регионами из брифа и запиши `frequency` (= `totalCount`, показов/мес), `exists`, `variants_found` в `01_masks.json`. Зафиксируй в `_state.json` → `wordstat_mcp_available: true|false`.

Ниже — **фолбек без MCP**: прямой доступ к Yandex Cloud Search API. Wordstat теперь живёт внутри **Yandex Search API** (Yandex Cloud AI Studio). Метод `topRequests`:
`POST https://searchapi.api.cloud.yandex.net/v2/wordstat/topRequests`, заголовок `Authorization: Api-Key <key>`.

**Что нужно для доступа** (вписывается в файл `.env` в корне проекта, под `.gitignore`; шаблон — `.env.example`):
- `WORDSTAT_API_KEY` — API-ключ из Yandex Cloud AI Studio, привязанный к сервисному аккаунту (тот же ключ, что для YandexGPT).
- `WORDSTAT_FOLDER_ID` — `folder_id` каталога Yandex Cloud (**обязателен** в каждом запросе).
- Проверка подключения: `python -m scripts.wordstat_api --check --regions 213`. Записывай результат в `_state.json` → `wordstat_api_available: true|false`.
- Если ключа нет — задай маркетологу: «Подключён Yandex Cloud Search API (Wordstat)? Если нет — пришли API-ключ + folder_id или попроси администратора создать сервисный аккаунт (см. https://yandex.cloud/ru/docs/search-api/concepts/wordstat).»

**Что делаем (фолбек):**

Берём 7-10 перспективных комбинаций из расширенной матрицы (не всё подряд — бережём квоту), пишем в `_masks_seed.txt` (по фразе на строку) и прогоняем:
```
python -m scripts.wordstat_api --mode masks --phrases-file _masks_seed.txt \
    --regions <из брифа> --output 01_masks_freq.json   # сырой вывод скрипта
```
На выходе по каждой маске: `frequency` (= `totalCount`, показов/мес), `exists`, `variants_found`.

Смотрим:
1. **Подтверждение существования.** Если `+ботаническая +панно` = 0 или <150/мес — нерабочая, помечаем «не существует»/«ниже порога».
2. **Новые идеи масок.** В ответе `associations` (ассоциации) часто появляется неучтённое (для `+премиум +картины` — «галерея современного искусства», «арт-объект»). Добавляем как кандидаты. ⚠️ `associations` может прийти пустым на узкой нише — это норма, не ошибка.
3. **Зеркала продукта.** Ассоциации подсказывают товарозаменители, которые мы пропустили.

Делаем 1-2 итерации. Больше — диминишинг рут.

⚠️ Операторы Wordstat (`!`, `+`, `[]`, кавычки) метод **не поддерживает** — фразы шлём без операторов, нормализованные.

⚠️ Если доступа к Wordstat API нет (`--check` упал, нет ключа или среда не запускает код) — частотности масок **пробиваем через браузер пользователя** (`references/wordstat-browser.md`; нужен инструмент управления браузером, например `claude-in-chrome`), а не прикидкой. Пробив делает оркестратор. Непробитые фразы помечаем `frequency: n/a`.

**Браузера в среде тоже нет** — маски остаются без частотностей: `01_masks.json` заполняется с `frequency: n/a` по всем строкам, отсев по порогу не выполняется, курирование идёт по смыслу. В `01_masks_wordstat_log.md` — пометка: «пропущено: нет доступа к Вордстату — частотности масок не пробиты. Потеряно: отсев пустых масок и вход для расчёта Шага 2. Как добрать: пробить маски на wordstat.yandex.ru и вернуться на Шаг 1». На гейте скажи это словами: без частотностей второй гейт подтверждает только направление, а не рабочий список.

### 4.4 Минимальный порог частотности

**Запросы <150 показов/мес не берём.** Шум, без объёма.

Маски, дающие `маска + общее` <150 — **не отбрасываем сразу**. Может быть НЧ-маска для группы, реальный объём наберётся из хвоста. Пометь «низкая прямая частотность, но включаем — проверим хвостом». Финальное решение — на гейте.

## Шаблоны масок по типу спроса

### Срочный спрос (active demand)
**Признаки:** клиент в моменте, решение за минуты, лояльности к бренду нет.
**Примеры:** эвакуатор, такси, замки/двери экстренно, сантехник, грузчики, ветеринар скорая.

**А (сужающие):** `+срочно`/`+быстро`/`+15минут`, `+круглосуточно`/`+ночью`/`+24часа`, `+ДТП`/`+авария`/`+послеаварии`, `+штрафстоянка`/`+спецстоянка`, `+межгород`/`+регион`, `+фиксированная`/`+безпереплат`, `+грузовой`/`+легковой`/`+спецтехника`.

**Б (общие):** `эвакуатор` ↔ `буксировщик` ↔ `тягач`; `такси` ↔ `подвозить`; `сантехник` ↔ `мастер` ↔ `слесарь`.

**НЕ делаем:** премиум-сужающие (убивают CTR), эмоциональные («ваш надёжный партнёр» — РСЯ-стиль), `+дёшево` (в панике готовы переплатить).

**Частотность:** `+срочно +эвакуатор` обычно 800-3000/мес в крупном городе. Города: умножай на население (Казань ≈ Москва × 0.15).

### B2B SaaS
**Признаки:** покупает малый бизнес/ИП, длинный цикл сделки, решение цифрами.
**Примеры:** CRM, ERP, бухучёт, онлайн-кассы, программа лояльности, чат-боты, аналитика.

**А (сужающие):** `+самозанятых`/`+ипшников`/`+малогобизнеса`, `+альтернативаYclients`/`+альтернатива1с`, `+бесплатная`/`+пробныйпериод`, `+мобильное`/`+воблаке`, `+сети`/`+филиалов`, `+ниши` (для CRM салонов — `+салона`, `+медцентра`, `+автосервиса`).

**Б (общие):** `CRM` ↔ `программа учёта` ↔ `система записи` ↔ `онлайн-журнал`; `бухгалтерия` ↔ `учётнаясистема`; `касса` ↔ `онлайнкасса` ↔ `чекпринтер`.

**НЕ делаем:** путать B2B и B2C (`купить CRM` ≠ `онлайн запись маникюр`), консьюмерские триггеры (`+скидка`, `+акция`), срочность в B2B иначе работает («к концу квартала», не «сейчас!»).

**Частотность:** категорийный ВЧ (`crm для салона`) 1500-5000; альтернатива (`yclients альтернатива`) 200-800, тёплый; сегментные НЧ (`crm для самозанятых мастеров`) 50-200, конверсионный.

### Премиум-сегмент
**Признаки:** высокий чек, отстройка от масс-маркета через эксклюзивность.
**Примеры:** авторская живопись, элитная недвижимость, luxury-часы, дизайнерская одежда, путешествия.

**А (сужающие):** `+премиум`/`+элитный`/`+эксклюзивный`/`+luxury`/`+vip`, `+авторский`/`+единственный`/`+вединственномэкземпляре`, `+коллекция`/`+галерея`/`+художника`, `+статусный`/`+представительский`, `+дорогой`.

**Б (общие):** `картины` ↔ `живопись` ↔ `арт`; `часы` ↔ `хронограф` ↔ `швейцарские`; `недвижимость` ↔ `апартаменты` ↔ `пентхаус`.

**НЕ делаем:** `+недорого`/`+скидка`/`+акция` (убивает позиционирование), `+оптом` (другая категория), массмаркет-конкурентов.

**Частотность:** ВЧ (`+премиум +картины`) 800-3000/мес в Мск+СПб; НЧ (`+единственный +экземпляр +художника`) 50-150 — аудитория-самородок. Большинство премиум-масок в Direct — НЧ, не пугайся.

### Ручная работа / на заказ
**Признаки:** товар изготавливается индивидуально, цикл дни/недели, готовы ждать.
**Примеры:** картины ручной работы, мебель на заказ, торты, авторская керамика, шитьё на заказ.

**А (сужающие):** `+ручной`/`+ручнойработы`/`+руками`/`+handmade`, `+подзаказ`/`+назаказ`/`+поразмеру`/`+померкам`, `+авторский`/`+мастер`/`+изготовление`, `+уникальный`/`+единственный`, `+пофото`/`+поэскизу`.

**Б (общие):** `картины` ↔ `панно` ↔ `постеры авторские` ↔ `холсты` ↔ `гобелены`; `торт` ↔ `капкейк` ↔ `десерт`; `мебель` ↔ `кухня` ↔ `шкаф`.

**НЕ делаем:** `+быстро`/`+срочно` (противоречит сути), `+дёшево` (массмаркет всегда дешевле), товарозаменители из принт-сегмента (`+постер модульный` — дешевле, сольёт CTR).

**Частотность:** категорийные (`картина ручной работы`) 500-2000; с кастомизацией (`картина по фото на заказ`) 1000-3000, горячо; премиум-маркеры (`+авторский`) 200-500.

### Массовый сформированный спрос
**Признаки:** клиент знает что ищет, выбирает по цене/сроку. Маркетплейсы доминируют.
**Примеры:** доставка пиццы, ремонт телефонов, уборка, химчистка, билеты на самолёт.

**А (сужающие):** `+рядом`/`+недалеко`/`+вмоёмгороде`, `+сегодня`/`+24часа`/`+быстро`, `+гарантия`/`+бесплатно`/`+срочно`, `+отзывы`/`+рейтинг`, `+круглосуточно`/`+24`.

**Б (общие):** `доставка пиццы` (нет товарозаменителей); `ремонт айфон` ↔ `ремонт смартфон` ↔ `починить телефон`; `уборка квартиры` ↔ `клининг` ↔ `генеральная уборка`.

**НЕ делаем:** премиум-маркеры, экзотические сужающие (десять прилагательных уводят в НЧ-хвост без объёма).

**Частотность:** категорийные ВЧ (`доставка пиццы`) 5000-30000, дорогой клик; с локацией (`пицца Нижний Новгород`) 500-2000, дешевле. Часто проигрывает маркетплейсам — лучше уходить в гипотезы отстройки.

### Default
Если ниша экзотическая (астролог для бизнеса, осиновые колья, b2b-консалтинг для оборонки):
1. Сужающие = строго из брифа маркетолога. Не выдумываем.
2. Общие = название продукта + 1-2 очевидных товарозаменителя.
3. Синонимов минимум — лучше пропустить, чем притащить нерелевантное.
4. Помечай: `niche_template: default`.
5. На гейт быстрее обычного.

## Стиль работы

- **Сначала направление, потом детали.** Гейт 1 — короткий.
- **Не "гладкая речь", а структура.** Артефакт в файл, в чате — таблица + пара выводов.
- **"Не существует в Wordstat" > "выдуманная маска".**
- **Не путать синонимы.** Языковые ≠ смысловые. Премиум = элитный (языковой). Картина ↔ панно (смысловой).
- **Не уходи в стратегию.** Если у маркетолога новые идеи углов — фиксируй в `01_masks_wordstat_log.md` и предлагай поправить бриф (поле 7), а не запускай новый этап.

## Артефакты

- `01_masks_matrix.md` — две колонки с синонимами, для маркетолога.
- `01_masks_freq.json` — **сырой вывод** `scripts.wordstat_api --mode masks`: что скрипт получил от Wordstat по каждой пробитой фразе (`frequency`, `exists`, `variants_found`). Промежуточный файл, дальше по пайплайну не используется.
- `01_masks.json` — **рабочий артефакт**, вход для Шагов 2 и 3. Собирается из `01_masks_freq.json` после анализа: выбрасываем маски ниже порога 150 показов/мес и несуществующие, добавляем найденные в ассоциациях кандидаты (они пробиваются следующей итерацией), проставляем `status`. То есть `01_masks.json` — это курированный результат 1-2 итераций, а не переименованный вывод скрипта.
- `01_masks_wordstat_log.md` — что пробивали, что отбросили (для воспроизводимости).
- `_anchors.txt` — якоря для рекурсивного сбора (Шаг 3): основы продуктовых слов колонки Б + синонимов, по одной на строку. Пример для картин: `картин`, `панно`, `холст`, `гобелен`. Основа = слово без изменяемого окончания (`картины`/`картин`/`картина` → основа `картин`), чтобы якорь ловил все словоформы.

## Связи в пайплайне

- **Вход:** `00_brief.md` (поле 7 — УТП и сужающие, поле 1 — продукт, поле 3 — регион).
- **Tool:** Yandex Cloud Search API Wordstat (`topRequests`) через `scripts/wordstat_api.py` — Фаза 4. При недоступности — режим симуляции.
- **Выход:** `01_masks.json` → вход для:
  - `frequency-calculator` (Шаг 2 — оценка CPC по живому аукциону)
  - полного сбора семантики (Шаг 3 — seed-фразы для Wordstat)
  - `wordstat-filter` (Шаг 4 — порог 150)
  - рекурсивного сбора семантики (Шаг 3): `01_masks.json` → широкие слова колонки Б в `_masks_seed.txt`, их основы в `_anchors.txt`
