# Субагент «semantics»: сбор семантики + кластеризация (Шаги 3-4)

> ⚠️ **Это НЕ отдельный скилл, а инструкция для дочернего агента.** Файл специально
> называется `semantics.md`, а не `SKILL.md`, чтобы в пакете скилла остался ровно один
> `SKILL.md` (корневой) и установщик Claude не ругался на «два SKILL.md».
>
> **Как запускается:** оркестратор (корневой `SKILL.md`) на Шагах 3-4 порождает дочерний
> агент через инструмент субагентов/форка среды (например, в Claude Code — Task с
> `subagent_type: general-purpose`, набор тулов `Bash Read Write Grep Glob`), передаёт ему
> текст этого файла и три аргумента: `slug`, `регионы`, `необходимая_частотность`. Если среда
> не умеет дочерних агентов — оркестратор выполняет эти же шаги инлайн. Сам по инициативе
> модели этот субагент не запускается.
>
> **Что нужно от среды здесь:** чтение и запись файлов — обязательно. Доступ к Wordstat —
> необязателен, но нужен хотя бы один из двух: MCP `yandex-wordstat` (основной путь) или
> запуск кода (Python) + ключ Cloud Search API (фолбек `scripts/wordstat_api.py`). Без обоих
> частотности не пробиваются, и тогда ты не выполняешь этот шаг сам, а возвращаешь оркестратору
> отказ с причиной, чтобы он пошёл по браузерной ветке Шага 3 (браузерных инструментов у тебя
> нет). Требования всего пакета — в разделе «Что нужно от среды» корневого `SKILL.md`.

Ты — изолированный субагент Шагов 3-4 пайплайна создания (`semantics`). Тебя запустил оркестратор
`yandex-direct-manager`. Истории основного разговора у тебя нет — только эта задача и
аргументы. Собери полную семантику через Wordstat, кластеризуй её и верни наверх **короткую сводку**,
а не простыни. Полный CSV семантики (тысячи ключей) остаётся в файле, в ответ его не выводи.

За один прогон ты даёшь **два** результата: (A) **сбор** сырой семантики волнами и (B)
**кластеризацию** на 4 CSV под Поиск/РСЯ по порогам частотности.

## Вход

- `$0` — slug кампании (папка `direct-campaigns/<slug>/`)
- `$1` — регионы (region_ids или названия из брифа)
- `$2` — необходимая суммарная частотность (из `02_frequency.json`, с ×2 запасом)

Чего нет в аргументах — возьми из `direct-campaigns/$0/_state.json` (slug, регион,
`wordstat_api_available`), `direct-campaigns/$0/02_frequency.json` (необходимая частотность) и
`direct-campaigns/$0/01_masks.json` (рабочие маски + продуктовые слова колонки Б).

## Методология (обязательное чтение)

Прочитай по пути от корня скилла создания (из форка путь не резолвится — пробуй путь от корня
скилла `yandex-direct-manager`):

- `references/wordstat-mcp.md` целиком — пробив частотностей через MCP `yandex-wordstat`
  (`wordstat_shows_batch`) и цепочка путей расширения семантики (скрипт Cloud API / комбинаторика /
  браузер), профили и стоп-условия
- `references/wordstat-filter.md` целиком — пороги НЧ<350 / СЧ 350-750 / ВЧ>750, минимум 150
  показов/мес, правила распределения Поиск/РСЯ и edge-кейсы (срочный спрос / премиум / B2B /
  ручная работа).

## Шаг A. Расширение семантики и пробив частотностей

Подготовь два файла в рабочей папке (нужны для пути 1):

- `direct-campaigns/$0/_masks_seed.txt` — стартовые семена: узкие комбинации из `01_masks.json`
  **плюс широкие одиночные слова продукта** (база колонки Б + синонимы). Широкие слова обязательны —
  без них волна 0 узкая. По одной фразе на строку.
- `direct-campaigns/$0/_anchors.txt` — якоря-основы продуктовых слов колонки Б + синонимов, по
  одному на строку. Запрос становится семенем следующей волны, только если содержит хотя бы один
  якорь — это держит рекурсию в теме продукта.

⚠️ **Через MCP `yandex-wordstat` доступен только пакетный пробив частотностей**
(`wordstat_shows_batch`, до 1000 фраз за вызов); расширение семантики он не делает — рекурсивных
волн, ассоциаций и похожих запросов на сервере нет. Пути расширения и их приоритет —
`references/wordstat-mcp.md` → «Шаг 3». Расширение делается скриптом Cloud API либо комбинаторикой
масок, а MCP пробивает частотности готового списка.

**Путь 1 (предпочтительный) — скрипт Cloud Search API** (есть запуск кода и ключ `WORDSTAT_API_KEY` +
`WORDSTAT_FOLDER_ID`). Запусти (профиль «Стандарт»):

```
python -m scripts.wordstat_api --mode semantics \
    --phrases-file direct-campaigns/$0/_masks_seed.txt \
    --anchors-file direct-campaigns/$0/_anchors.txt \
    --regions "$1" \
    --output direct-campaigns/$0/03_semantics_raw.csv
```

Скрипт волнами собирает похожие запросы **и ассоциации**, дедуплицирует, углубляется на найденных
запросах и **гарантированно останавливается** (по затуханию или предохранителям). В конце печатает
причину остановки, число вызовов API, время и число волн — запомни их для сводки.

**Путь 2 — комбинаторика + пакетный пробив через MCP** (когда есть только MCP, без ключа Cloud).
Сгенерируй кандидатов из `01_masks.json` (продуктовые слова × сужающие × модификаторы намерения ×
словоформы, 300–1000 штук), пробей одной-двумя пачками `wordstat_shows_batch(keywords, region_id=$1)`,
отсей `stat < 150`, сделай одну волну углубления. Детали — `references/wordstat-mcp.md` → «Шаг 3, путь 2».
`source = combinatorial`. **Обязательная пометка о пропуске** «нет расширения семантики через Вордстат»
(текст — в `references/wordstat-mcp.md`) идёт в `03_semantics_raw.csv` и в сводку.

**Артефакт:** `03_semantics_raw.csv` со столбцами `keyword,frequency,mask_parent,source,depth`.

🚫 Не выдумывай частотности: непробитая фраза — либо `frequency: n/a` с пометкой, либо не в файле.

**Если собранной суммарной частотности не хватает до `$2`** — на пути 1 перезапусти с профилем
«Глубокий» (флаги `--max-depth 3 --seeds-per-wave 300 --dry-threshold 0.03 --max-api-calls 5000 --max-minutes 40`).

**Если ни MCP, ни ключа Cloud нет** — у тебя (форк) **нет инструмента управления браузером**, поэтому
сам частотности не пробьёшь. Верни наверх флаг **API_НЕДОСТУПЕН**: браузерный пробив (путь 4) через
сессию пользователя (`references/wordstat-browser.md`) делает **оркестратор** в основном контексте.
В `03_semantics_raw.csv` запиши то, что удалось собрать без частотностей (если что-то есть),
поставь в колонке `frequency` значение `n/a` и зафиксируй в сводке пометку о пропуске:
«пропущено: нет доступа к Вордстату — частотности не пробиты, пробив предстоит оркестратору».

## Шаг B. Кластеризация (НЧ/СЧ/ВЧ + Поиск/РСЯ)

По `references/wordstat-filter.md` разложи `03_semantics_raw.csv`. Значимы столбцы
`keyword,frequency,mask_parent`. Пороги: НЧ <350, СЧ 350-750, ВЧ >750 показов/мес; минимум 150 —
иначе в отброшенные. Учитывай каналы и тип ниши (Поиск/РСЯ/оба, бюджет) из `_state.json` / брифа.

Напиши в `direct-campaigns/$0/`:

- `04_keys_search_obligatory.csv` — НЧ + СЧ для Поиска (база)
- `04_keys_search_vch.csv` — ВЧ для Поиска (только при бюджете ≥100к + массовый продукт + бренд)
- `04_keys_rsya.csv` — СЧ + ВЧ для РСЯ
- `04_keys_excluded.csv` — отброшенные с причиной (ниже 150 / дубль / не в тему)
- `04_wordstat_filter_summary.md` — краткий отчёт по распределению

**Схема столбцов** — одна на все четыре CSV, канонический источник `references/wordstat-filter.md` → «Артефакты»:

```
keyword,frequency,freq_tier,narrowing,channel,status,notes
```

Ключевое: колонка `narrowing` (сужающее слово `+премиум` / `+срочно`, либо `all`) **обязательна** — по ней Шаг 5 раскладывает ключи по кампаниям. В `04_keys_excluded.csv` колонка `status` несёт причину отброса.

## Что вернуть наверх (КРИТИЧНО)

Сырьё CSV и полные таблицы НЕ выводи. Верни **только это**, ≤ 20 строк:

```
СВОДКА ШАГОВ 3-4 — Семантика (slug: $0)
- Собрано ключей: N (волн W · вызовов API C · причина остановки: <...>)
- Путь расширения: cloud-api | combinatorial | list | browser
- Распределение: обязательные Поиск (НЧ+СЧ) X · ВЧ Поиск Y · РСЯ Z · отброшено E
- Суммарная частотность: собрано ≈<F> vs нужно <$2> → [OK | НЕДОБОР Δ<...>]
- Артефакты: 03_semantics_raw.csv, 04_keys_search_obligatory.csv, 04_keys_search_vch.csv,
  04_keys_rsya.csv, 04_keys_excluded.csv, 04_wordstat_filter_summary.md
- ⚠️ Ограничения: <API_НЕДОСТУПЕН — нужен браузерный пробив оркестратором / мало данных / недобор частотности>
```

Оркестратор покажет сводку человеку на гейте Шага 4. Если частотность недобрана — ты только
помечаешь флаг **НЕДОБОР**; решение «вернуться на Шаг 1 и расширить маски» принимает оркестратор с
маркетологом, не ты.
