# Дизайн: две модели РК (ЕПК с комбинированным объявлением + классика) с выбором на гейте

Дата: 2026-07-08
Скилл: `yandex-direct-create-pipeline`

## Контекст

Сейчас скилл зашивает **одну** структуру кампаний (Шаг 5 → `campaign-structure.md`):
Поиск и РСЯ — всегда отдельные кампании; внутри группы тест-матрица из 3-5 текстово-графических
объявлений; действует жёсткий потолок «>6 Поиск-кампаний — много, объедини».

Яндекс.Директ сместился к модели **ЕПК (Единая перфоманс-кампания) с комбинированным
объявлением**: одна кампания с одним объявлением, которое содержит несколько заголовков, текстов,
картинок и видео, а Яндекс сам собирает лучшую комбинацию и для Поиска, и для РСЯ. Это убирает и
разделение Поиск/РСЯ на отдельные кампании, и ручную тест-матрицу.

## Цель

Дать скиллу **две полноценные ветки** структуры и объявлений и **гейт выбора** между ними, где
маркетолог видит **плюсы и минусы каждого подхода**, а ЕПК помечена как **рекомендованная**.
Дополнительно — снять жёсткий потолок на число кампаний в запуске.

Специалист лучше знает, что ему нужно, — задача скилла честно показать выбор и провести по выбранной
ветке, не навязывая.

## Решения (согласовано с пользователем)

1. **Две полноценные ветки**, не «основная + сноска»:
   - **`epk_combined` (рекомендованная):** 1 РК = 1 группа = 1 комбинированное объявление; Поиск и
     РСЯ **не** разделяются на отдельные кампании.
   - **`classic`:** текущая модель без изменений (отдельные Поиск/РСЯ-кампании, тест-матрица 3-5
     объявлений на группу).
2. **Гейт выбора с плюсами/минусами** — маркетолог на одном из шагов встречает явный выбор с
   таблицей «плюсы / минусы» обеих моделей и пометкой рекомендации на ЕПК.
3. **«РК без ограничений»:** снять жёсткий потолок на число кампаний; оставить только **мягкую
   подсказку** про дробление при малом бюджете (не блокирует).
4. **Честная заливка:** текущий MCP умеет только `TextCampaign` + классический `TextAd`.
   Комбинированное объявление через `ads_add` **не создаётся** — в ЕПК-ветке оно заливается руками
   (Директ Коммандер/UI) или через passthrough `yandex_direct_api_call` (в коде MCP пока нет).
   Скилл не делает вид, что зальёт комбинированное автоматически.

## Гейт выбора модели

**Место:** в начале **Шага 5** (структура кампаний), до построения структуры. Это самый ранний
момент, где выбор реально влияет (Шаги 1-4 — сбор/кластеризация семантики — от модели не зависят).

**Хранение:** в `_state.json` добавляется поле `ad_model` со значением `"epk_combined"` или
`"classic"`. Оно переключает поведение Шагов 5, 8, 9, 10. При возобновлении скилл читает `ad_model`
и не спрашивает заново.

**Что показывает гейт (плюсы/минусы):**

| | 🟢 ЕПК + комбинированное (рекомендуем) | ⚪ Классическая |
|---|---|---|
| Структура | 1 РК = 1 угол, одно объявление на Поиск+РСЯ | Поиск и РСЯ — отдельные РК, 3-5 объявлений/группа |
| Плюсы | меньше сущностей, Яндекс сам подбирает связку, быстрый старт, единый бюджет на угол | полный ручной контроль текстов под Поиск и под РСЯ по отдельности, раздельная статистика Поиск/РСЯ, привычно |
| Минусы | меньше ручного контроля над тем, что где покажется; статистика Поиск/РСЯ смешана; **комбинированное объявление MCP не зальёт — руками** | больше кампаний и объявлений вести; медленнее собирать; тест-матрицу надо придумывать самому |
| Кому | большинству запусков, особенно с ограниченным временем | когда нужна тонкая раздельная настройка Поиск vs РСЯ |

Прямой вопрос: «Рекомендую ЕПК с комбинированным объявлением. Берём ЕПК или классику?»

## Ветка `epk_combined`

**Структура (правит `campaign-structure.md`, новый раздел):**
- **1 угол / сегмент / лендинг → 1 РК.** Премиум, Срочно, Бренд, B2B — каждый своя РК. Внутри —
  1 группа, 1 комбинированное объявление.
- Разделения Поиск/РСЯ на кампании **нет** — одна РК обслуживает оба размещения.
- Ключи Шага 4 идут в эту же РК: НЧ/СЧ/ВЧ как ключевые фразы + автотаргетинг для сети. **CSV Шага 4
  не меняются** — меняется только сборка структуры на Шаге 5.
- `05_campaign_structure.json` получает поле `ad_model: "epk_combined"` и на кампанию — признак
  `combined: true`.

**Комбинированное объявление (правит `ad-copywriting.md` + `yandex-direct-specs.md`):**
- Несколько заголовков и несколько текстов (точные лимиты по количеству вариантов — из
  `yandex-direct-specs.md`, см. «Открытые пункты») + картинки/видео из ассетов брифа.
- Посимвольные лимиты переиспользуют классические: Заголовок 1 ≤56, Заголовок 2 ≤30, Текст ≤81.
- **Обязательное вхождение ключа** хотя бы в один заголовок.
- Заменяет тест-матрицу 3-5 объявлений: мультивариантность живёт внутри одного объявления.

**Стратегия торгов (правит `bidding-strategy.md`):** для ЕПК стартовая логика та же по духу
(не начинать с «Оптимизации конверсий»), но без раздельных Поиск/РСЯ-фаз — единая кампания, единая
стратегия. Раздел получает короткую врезку «для ЕПК».

**Визуалы (правит `rsya-creatives.md`):** картинки/видео теперь часть комбинированного объявления,
а не отдельная РСЯ-заглушка. Если ассетов нет — объявление заливается без них (плейсхолдер-TODO
остаётся), но раздел перестаёт считать РСЯ-визуалы «отдельным шагом только для РСЯ».

## Ветка `classic`

Без изменений. Вся текущая логика `campaign-structure.md` (разделы 1-7, группы, тест-матрица) и
Шага 8 остаётся как есть и применяется, когда `ad_model = "classic"`.

## Заливка (Шаг 10) — честно

- Общее (обе ветки): MCP создаёт что может (`campaigns_add` как `TextCampaign`, `adgroups_add`,
  `keywords_add`); стратегия, цели Метрики, минусы, sitelinks/callouts — уже сейчас частью руками
  (см. `mcp-account-integration.md`, `yandex-direct-mcp-gaps.md`).
- **`epk_combined`:** комбинированное объявление через `ads_add` **не создаётся**. Пути:
  1. если появится passthrough `yandex_direct_api_call` — через него;
  2. иначе — руками в Директ Коммандере / UI по артефакту `08_creatives.json`.
  Всё, что MCP не залил, — в `10_launch_log.md` списком «доделать руками» (механизм уже есть).
- **`classic`:** как сейчас — `ads_add` создаёт `TextAd`.

## Артефакты и схема

- `assets/creatives_schema_example.json`: добавить форму комбинированного объявления — массивы
  `titles[]`, `texts[]`, `assets[]` (image/video) на объявление, с полем `ad_model`. Классическая
  форма остаётся.
- `scripts/generate_ads_xlsx.py`: уметь вывести комбинированное объявление (несколько
  заголовков/текстов в строках) с валидацией посимвольных лимитов и лимита на число вариантов;
  классический путь сохраняется. При отсутствии `openpyxl` — CSV-фолбек, как сейчас.
- `_state.json`: поле `ad_model`.
- `05_campaign_structure.json`: поля `ad_model`, `combined`.
- `08_creatives.json`: комбинированная форма при `ad_model = "epk_combined"`.

## Вне объёма (YAGNI)

- Не трогаем сбор и кластеризацию семантики (Шаги 1-4) и субагент `semantics`.
- Не пишем новый код MCP / passthrough `yandex_direct_api_call` — только фиксируем ручной путь.
- Не добавляем смарт-баннеры, динамические, мобильные, медийные кампании.
- Не меняем классическую ветку по сути — только изолируем её под `ad_model = "classic"`.

   ЕПК тоже уходит в ручной/passthrough путь, отразить в Шаге 10.
